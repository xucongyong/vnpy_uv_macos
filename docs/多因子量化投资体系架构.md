# 多因子量化投资体系架构规划与实施指南
## (Industrial Multi-Factor Alpha Architecture Plan)

> **版本**：v1.0 | **规划日期**：2026-09-23  
> **适用**：本量化系统（VeighNa 4.3 + PostgreSQL 远程库 + 海外自动化执行机）  
> **目标**：从“单一规则 CTA 策略”进化到“工业级多因子挖掘、评估、合成与组合投资体系”。

---

## 一、为什么需要多因子框架？（核心痛点与解法）

| 现状痛点（单一规则策略） | 升级后（多因子组合体系） |
| :--- | :--- |
| **容易大幅回撤**：行情风格一变（如趋势变震荡），策略立即失效并持续亏损。 | **对冲平滑回撤**：动量、均值回归、波动率、量价等多个低相关性因子互相补足，极大熨平净值曲线。 |
| **缺乏科学评估标准**：只看最终回测赚不赚钱，不知道收益到底来自运气还是真实规律。 | **严格的量化体检**：通过 IC (信息系数)、IC_IR (稳定性)、分层多空收益率客观评估因子质量。 |
| **策略扩张困难**：写一个新策略就要写一套独立的买卖、止损、仓位逻辑，代码冗余。 | **积木式工厂开发**：每天只需写一个纯数学因子函数，系统自动计算、自动评估、自动纳入策略组合。 |

## 四、因子书写规范（标准极简）

为了让你或 AI 以后**“每天随手就能写一个新因子”**，所有因子统一遵循简单的函数规范：
- **输入**：标准历史日线 `DataFrame`（含 `open, high, low, close, volume`）
- **输出**：一个 `Series`（对应每根 K 线的因子数值）

示例（极其直观，5 行代码就是一个因子）：

```python
from gemini_quant.factors.base import register_factor

@register_factor(name="volatility_breakout", category="volatility", desc="波动率突破因子")
def factor_volatility_breakout(df):
    """当今日振幅突破过去20天平均振幅，且收盘价创近10日新高时为正信号"""
    daily_range = (df["high"] - df["low"]) / df["close"]
    range_ma20 = daily_range.rolling(20).mean()
    is_high10 = df["close"] > df["close"].shift(1).rolling(10).max()
    return (daily_range / (range_ma20 + 1e-6)) * is_high10.astype(int)
```

系统会自动发现该因子，并自动纳入每日的体检和回测。

## 五、分步落地实施路线图 (Step-by-Step Roadmap)

我们将整个体系拆分为 **4 个清晰明确的阶段**，一步一步扎实推进：

### 阶段 1：底座与首批核心因子库（Step 1）
- [ ] 创建 `gemini_quant/` 标准目录骨架与统一基类。
- [ ] 封装首批精选的 **15~20 个高价值基础因子**（涵盖经典动量、布林突破、RSI、Alpha101 中的核心因子）。
- [ ] 确保与远程 PostgreSQL（`postgres.quant_data`）数据加载无缝兼容。

### 阶段 2：因子质量评估与体检引擎（Step 2）
- [ ] 实现 `gemini_quant/evaluation/` 模块（计算 IC、Rank IC、IC_IR、未来 1/3/5 日预测能力）。
- [ ] 开发 `run_factor_eval.py`：单命令运行，自动跑出自选股池上的所有因子表现排行榜。
- [ ] 建立淘汰机制：明确哪些因子是“有效因子”，哪些是“噪声因子”。

### 阶段 3：多因子合成策略与组合回测（Step 3）
- [ ] 实现多因子打分器（Z-Score 标准化 + IC_IR 动态权重配比）。
- [ ] 生成多因子 Alpha CTA 策略，接入 VeighNa 引擎回测对比单一策略的提升效果。
- [ ] 验证回撤是否显著降低、夏普比率是否明显提升。

### 阶段 4：自动化流水线与每日执行闭环（Step 4）
- [ ] 将因子评估与合成模型无缝整合进 `daily.py`。
- [ ] 每日 16:30 在海外服务器上跑行情同步时，自动更新因子评分和标的推荐榜。
