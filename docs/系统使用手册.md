> 更新: 2026-08-28 | 适用: 本量化项目 (VeighNa/vn.py 4.3 + 远程 PostgreSQL)

## 一、系统是什么（30 秒看懂）

这是一个**日线量化回测系统**：
- **数据来源**：akshare 免费抓取 A股/港股/美股 日线行情
- **数据存储**：远程 PostgreSQL 数据库（`v.xucongyong.com` 的 `quant` 库）
- **策略**：自己写 Python 类（继承 vnpy 的 `CtaTemplate`），写均线/布林/RSI 等交易逻辑
- **回测**：用历史数据模拟交易，看这个策略赚不赚钱

一句话：**抓数据存库 → 写策略 → 用历史数据回测 → 看赚不赚钱**。

## 二、数据流（核心，务必理解）

```
① 抓数据 (akshare)        ② 存数据库               ③ 回测读取
    scripts/save_watchlist.py → PostgreSQL quant 库  → run_backtest.py
                                  ┌─────────────┐
                                  │ 表 quant_data   │ ← 697万根K线
                                  │ 表 quant_data_sync│ ← 每只股票同步摘要
                                  └─────────────┘
```

**关键认知**：
- 数据**不存在文件里**，全在远程数据库。你本地找不到 .csv 行情，因为它们都在 `v.xucongyong.com` 的服务器上
- 回测脚本**自动从同一个库读数据**，所以你"存进去 = 回测马上能用"
- **"增量同步"** = 每次只下载"库里最新日期之后"的那几根K线，所以秒级完成；已存在的价格自动覆盖，不重复

### 3.2 表结构

| 表 | 内容 | 行数 |
|---|---|---|
| `quant_data.quant_data` | **K线数据**：symbol, exchange, datetime, open/high/low/close, volume | 697万 |

**唯一性保证**：表上唯一索引锁死 `(symbol, exchange, interval, datetime)`，数据库物理上不允许同一只股票同一时刻有两根K线。实测 697万行重复 = 0。

### 3.3 股票代码格式

`SYMBOL.EXCHANGE`，例如：
- A股：`000001.SZSE` / `600519.SSE` / `920000.BSE`
- 港股：`00700.SEHK`
- 美股：`AAPL.NASDAQ` / `TSLA.NASDAQ`

## 五、写策略教程（核心）

### 5.1 三步写一个策略

```bash
# ① 生成骨架（会创建一个文件 + 自动注册）
.venv/bin/python scripts/new_strategy.py --name 你的策略名 --kind ma
#   kind 可选: ma(均线) boll(布林) rsi(超买超卖) momentum(突破) template(空骨架)
```

```bash
# ② 编辑生成的 strategies/daily_日期_你的策略名.py
#    改参数 + 写买卖逻辑（见下面示例）
```

```bash
# ③ 回测验证
.venv/bin/python run_backtest.py --strategy 你的策略名 --symbol 00700.SEHK --start 2022-01-01
```

### 5.2 策略文件长什么样（核心理解）

```python
from vnpy_ctastrategy import CtaTemplate, BarGenerator, ArrayManager, BarData, ...

class MyStrategy(CtaTemplate):
    # ① 可调参数（回测时用 --params 覆盖）
    fast_window = 20
    slow_window = 60
    fixed_size = 100

    # ② 参数和变量声明（框架约定，必须写）
    parameters = ["fast_window", "slow_window", "fixed_size"]
    variables = []

    # ③ 初始化：加载历史K线预热指标
    def on_init(self):
        self.load_bar(200)

    # ④ ★ 核心：每来一根K线执行一次
    def on_bar(self, bar: BarData):
        self.am.update_bar(bar)          # 累积历史
        if not self.am.inited:           # 数据不够先等
            return

        fast = self.am.sma(self.fast_window, array=True)[-1]
        slow = self.am.sma(self.slow_window, array=True)[-1]

        # 金叉买入
        if fast > slow and self.pos == 0:
            self.buy(bar.close_price, self.fixed_size)   # 开多
        # 死叉平仓
        elif fast < slow and self.pos > 0:
            self.sell(bar.close_price, abs(self.pos))    # 平多
```

### 5.3 必须遵守的规则

| 规则 | 说明 |
|---|---|
| 继承 `CtaTemplate` | 必须 |
| 声明 `parameters` | 可调参数列表（回测 --params 覆盖的就是这些） |
| 声明 `variables` | 状态变量列表 |
| 交易逻辑写在 `on_bar` | 日线策略直接写；分钟线用 `BarGenerator` 聚合 |
| 下单只用 4 个方法 | `self.buy`（开多）/`self.sell`（平多）/`self.short`（开空）/`self.cover`（平空） |
| 持仓状态 `self.pos` | `>0` 持多，`<0` 持空，`0` 空仓 |

### 5.4 常用指标（`self.am` 提供）

- `self.am.sma(n)` 均线 | `self.am.boll(n, dev)` 布林带 | `self.am.rsi(n)` RSI
- `self.am.atr(n)` 波动 | `self.am.macd(...)` | `self.am.high/low/close` 数组

### 5.5 回测参数覆盖

```bash
# 不改代码，直接换参数对比
.venv/bin/python run_backtest.py --strategy dual_ma --symbol AAPL.NASDAQ \
  --params fast_window=5,slow_window=20,fixed_size=500 --csv
```

## 八、常见问题排查

| 症状 | 原因 | 解决 |
|---|---|---|
| 回测没数据 | 数据库没这只股票 | `scripts/save_watchlist.py --symbols 00700.SEHK` 先同步 |
| `TypeError: ... NoneType` (timezone) | `~/.vntrader/vt_setting.json` 不存在 | `mkdir -p ~/.vntrader && cp vt_setting.json ~/.vntrader/` |
| `找不到 vnpy_postgresql` | 从 deploy/ 目录跑，找不到项目里的 vnpy，或缺依赖 | 重跑最新 `deploy/patch_vnpy_postgresql.py`；`uv pip install ...` |
| 连接数据库超时 | 防火墙白名单没放行当前 IP | 阿里云安全组加 5432 放行 |
| 港股/美股同步失败 | 东财接口被拒 | save_watchlist 会自动降级新浪接口，稍后再试 |
| 策略列表变多/变少 | registry 自动扫描 | 新增/删除 strategies/*.py 即自动更新 |

## 九、重要注意事项（务必记住）

1. **vnpy 驱动被补丁过**：表名 `dbbardata→quant_data`、`dbbaroverview→quant_data_sync`，且不建 tick 空表。
   **如果重装/升级 vnpy_postgresql，补丁会丢失**，需要重跑 `deploy/patch_vnpy_postgresql.py`。
2. **vnpy 读配置在 `~/.vntrader/vt_setting.json`**，不是项目里的 `vt_setting.json`。改数据库配置要改家目录那个。
3. **本地 python 用 `.venv/bin/python`**，别用系统 python。
4. **代码风格**：`.venv/bin/ruff check .` 检查。
5. **数据最新同步到**：跑 `daily.py` 或 `save_watchlist.py` 更新。
6. **BTC 走另一条路**：`run_btc_ai.py`（yfinance + LightGBM），不经过这套日线回测。
7. **git 仓库是公开的**，注意别提交密码（数据库密码已在历史里，建议仓库设为私有）。
8. **报告 CSV 不入 git**（已加 .gitignore），只是本地生成物。
